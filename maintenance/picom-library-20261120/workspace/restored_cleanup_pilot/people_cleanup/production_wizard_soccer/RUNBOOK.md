## Algorithms and identity stay fixed

`engine.outer` calls the exact pinned pure v3 transform with `manual_seeds=()` for opaque512px sources, and preserves already-transparent pixels identically. Unexpected opaque dimensions are held. No v3 interior seeds, broadened threshold, erosion or automatic foreground deletion is added. The existing strict runner remains unchanged: reviewed strict-core alpha removal only, RGBmin240, spread20, alpha128, eight-connected components and256-at512 per-region minimum. Its broader computed matte result is discarded.

True original, immutable outer intermediate and final candidate remain distinct in every case and delivery record. Strict assertions compare against the outer intermediate. Final review compares against the TRUE original. Every hold keeps that whole exact original. Safe modest improvement uses existing policy-v2 `seal.accepts`. Every changed final requires an independent reviewer, including numeric no-inner cases; producer actors are also recorded and excluded as output reviewers. No Q80, source overwrite, Library publication or general pilot exists.

`engine.normalize_regions` follows the existing source compiler's full-component convention: omitted ROI defaults to the union of the selected **actual current component** bounds; seeds are derived inside that ROI. An explicit ROI stays explicit. Evidence gets a separate four-pixel native context crop clipped to image bounds. That crop never changes the selected strict mask, protections or minimum.

## Actual display and durable checkpoint contract

`review_evidence.Renderer` creates native before/after, informative blue/dark/alpha roles, and every actual region crop. Native roles are preferred. Physical PNGs are content-addressed per batch. The canonical cache stores compressed PNG bytes and string/hash metadata only; it does not retain decoded RGBA arrays across the batch. Every proposed alias decodes the cached canonical PNG and compares actual RGBA arrays before sharing bytes. A role alias is emitted only after canonical decoded RGBA arrays, dimensions and serialized pixels compare equal. Opaque original native/blue/dark can share one file; informative transparent final roles remain. Uniform alpha PNGs and equal roles across cases can share physical bytes, while each case retains explicit role coverage and its own independent review. Aliases preserve their first physical role, exact pixel hash and `equality_verified:true`; equality is never inferred from names or opacity alone.

Every eligible source case with an available partner also has `partner-stage-native.png` and `partner-original-native.png` roles, bound to the actual same-concept partner case, current partner stage/source paths and hashes, even when that partner is excluded numerically. The excluded partner still has no invented source decision or checkpoint. Source decisions bind `paired_context_sha256` and explicitly record `same_pose_support` (`supports_same_pose`, `different_pose` or `uncertain`) plus a reason after actual paired views. Different/uncertain partner poses never cause automatic ROI/mask sharing or establish pose equivalence. Each case retains its own current component selection and masks. For a held partner, the available case binds the exact absent opposite-style disposition and records `same_pose_support: partner_unavailable_generation_held` with a reason. Only its own actual native roles are present. Held targets have no image, evidence role, source or output decision, or checkpoint. Output checkpoints remain per case.

A reviewer supplies a JSONL display journal; the code never invents display events. Each physical file attempt records sequence, case/phase, actual tool event reference, unique display event ID, actual outer `exec_id`, `exec_file_index`, UTC, requested file path/SHA/native dimensions and exact roles. `outcome` is `complete`, `incomplete` or `failed`; incomplete/failed attempts retain an explanatory reason and contribute zero coverage. Complete attempts require actual native viewing. Genuine complete redisplays are allowed, with unique IDs and no duplicate role-coverage credit. A crop clipped by a tool can therefore be logged honestly, followed by a repeated whole view and a full crop retry. Repeated wholes never replace missing crop coverage.

At most **four physical file attempts per entire exec** are allowed, including failed/incomplete attempts and redisplays of the same file. Equality-alias roles can share one physical file event when explicitly listed. Inner Promise groups do not reset this limit. Source and output journals are checked together at batch closeout to prevent phase splitting from hiding a fifth file. `exec_id` must identify the real enclosing tool invocation, not an inner group; the code checks supplied observations but cannot authenticate a fabricated external tool reference.

Review logs are restricted to `batches/<batch-id>/review_logs/source.jsonl` and `output.jsonl`; checkpoints are restricted to `batches/<batch-id>/review_metadata/checkpoints/*.json`. These location/suffix guards run before any read/write. Image/evidence/stage destinations, including an accidentally reused PNG variable, are rejected without modifying their bytes. Even the internal append helper applies the same guard and refuses non-JSON existing log content.

`append_observed_display` persists caller-supplied actual-tool observations; `checkpoint_observed_case` validates complete role coverage, writes/fsyncs the immutable checkpoint and directory, then appends/fsyncs its journal event. Neither helper creates a viewing claim.

A case finishes with a `checkpoint` event pointing to an already durable immutable checkpoint JSON and its SHA. That file binds batch/case/phase, case index, event sequence, preceding checkpoint hash, exact source-decision or output-review hash, reviewer and UTC. The next case cannot start before this checkpoint. Partial displays, missing crops, wrong files/roles, reordered cases, broken checkpoint chains or silently changed review/source data fail. These are accountable tool-viewing assertions, not mathematical proof of a person's visual judgement.

Source choices are keyed only by eligible case IDs; each additionally binds the actual paired context and explicit same-pose-support assessment. They bind true-original SHA, current outer full-byte/RGBA SHA, component-inventory hash, actual reviewer/viewing, decision and selected current component labels/optional ROI/protections. `finish_batch` binds the exact source journal and root-approved source decision file. Numeric no-inner is permitted only if the current stage's **total** strict-white pixel count is less than the inherited minimum, proving every possible selected protected/ROI core is too small. Many small components whose combined total reaches the minimum are not skipped. Numeric exclusions have `visual_review_claimed:false` and no fabricated source reviewer.

Output reviews retain the established source/output hash, actual-view, full/region, reviewer, safety, worthwhile and reason fields. They additionally bind outer SHA, final-case canonical hash and exact evidence assets. Durable output checkpoint reviewer must match the review actor and differ from source reviewer and producers. Review selection is rederived from these immutable records during later closeout validation; a changed closed delivery row cannot silently select an intermediate or relabel a true original.

## Exact batch retirement and interruption

A first retirement refuses any PNG already missing or changed. Its durable intent binds closed-batch SHA, bundle/environment/renderer recipe, exact temporary PNG list and successful byte-for-byte regeneration. Interrupted deletion is resumable only against that exact intent; no missing file is silently treated as reviewed. Completion is written only after the allowed files are absent and live dependencies/authorities still match.

Final/global proof excuses an absent PNG only when a matching **completed** batch retirement receipt exists. Intent alone is insufficient. The final proof retains both receipt hashes and the retirement root approval. A present changed PNG still fails. Missing/changed masks, outputs, source bytes, journals, checkpoints, decisions, reviews or metadata always fail. Regeneration uses retained immutable outer/final candidates, true original hashes, exact normalized component crop geometry, pinned pure/strict algorithms and Python/NumPy/Pillow/SciPy versions. No population evidence has been retired by this staging task.

## Remaining limits

This remains synthetic validation, not population safety evidence or root execution approval. Real tool display logs and reviewer judgements still have to be supplied during authorized production. Metadata signature guards assume normal filesystem writers (dev/inode/size/mtime/ctime); admitted byte hashes are retained and global final authorities/bytes are checked afresh. No filesystem multi-file atomic transaction or protection against a privileged actor forging immutable evidence is claimed. An interruption during final canonical publication can leave non-authoritative artifacts after verification; the current pointer stays non-complete until the whole proof is published, and exact replay refuses differing artifacts. No time/credits estimate is inherited from old already-transparent People ratios.
